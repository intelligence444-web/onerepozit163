# Базовая SEO-оптимизация лендинга

Порядок работы, проверенный на ad-engine.ru и ad-engine.ru/landengine/. Каждый шаг — отдельный коммит, правки публикуются туда, откуда реально собирается сайт.

## 0. Найди, откуда собирается живой сайт

Прежде чем править, убедись, что правишь то, что видит поисковик.

- Скачай живую страницу (`curl -sL https://домен/ | head -40`) и сравни `<title>` с файлом в репозитории.
- Для GitHub Pages: ищи `CNAME` и ветку, из которой собирается Pages (обычно `main`). В старых рабочих ветках может лежать другая версия сайта без домена — правки туда никуда не попадут.
- Проверь живые `robots.txt` и `sitemap.xml`.

## 1. Аудит `<head>`

Запусти `python3 scripts/check_head.py путь/к/index.html [ещё страницы]` — он покажет длину title/description, наличие canonical, OG, Twitter, JSON-LD, число H1, картинки без alt. Затем исправь:

| Элемент | Правило | Почему |
|---|---|---|
| `<title>` | 55–80 символов, главный запрос в начале, бренд в конце через « — » | Яндекс обрезает длиннее ~80, первые слова весят больше |
| `description` | 140–170 символов, оффер + цифры + площадки | на позиции почти не влияет, но совпавшие слова выделяются жирным и поднимают CTR |
| `canonical` | абсолютный URL со слэшем на конце | склейка дублей (`/`, `/index.html`, с UTM) |
| `meta robots` | `index, follow, max-image-preview:large` на продающих; `noindex` на thanks, политике, согласии, концептах | |
| Open Graph | `og:title`, `og:description`, `og:type`, `og:url`, `og:image` (1200×630, абсолютный URL), `og:image:alt`, `og:site_name`, `og:locale=ru_RU` | превью в Telegram и ВК |
| Twitter | `twitter:card=summary_large_image`, title, description, image | |
| `theme-color`, `author` | цвет фона сайта, имя владельца | |
| JSON-LD | `ProfessionalService` (название, url, logo, image, телефон, priceRange, areaServed, founder, sameAs с соцсетями) + `FAQPage` | карточка компании и вопросы в выдаче Яндекса |

`meta keywords` не добавляй: Google не учитывает с 2009 года, у Яндекса вес минимальный, а переспам вредит. Если спросят — объясни, что ключи работают в title, H1/H2, тексте и FAQ.

Пример JSON-LD и готовые блоки — в `references/head-template.md`.

**FAQPage** генерируй из видимых вопросов страницы, а не руками: `python3 scripts/faq_jsonld.py страница.html` пересобирает `mainEntity` из блока `.faq` (`<details><summary>вопрос</summary><p>ответ</p>`). Текст в разметке должен совпадать с видимым, иначе Яндекс может проигнорировать разметку. После любой правки FAQ запускай скрипт снова.

Декоративные картинки оставляй с `alt=""` (иконки, логотип внутри ссылки с `aria-label`) — это правильно. Содержательные (фото, скриншоты работ) — с описанием.

## 2. sitemap.xml, robots.txt, 404

- `sitemap.xml`: только индексируемые страницы, абсолютные URL, `lastmod` обновляй после заметных правок.
- `robots.txt`: `Sitemap: https://домен/sitemap.xml`; закрывай служебные папки (`/server/`, `/tools/`). Страницы с `noindex` в robots **не запрещай** — иначе робот не сможет их открыть и не увидит noindex.
- robots.txt читается только из корня домена. На `user.github.io/repo/` он не работает — только после своего домена.
- `404.html` в корне с `noindex`, ссылками на главную по абсолютным путям (GitHub Pages отдаёт его на любой глубине).

## 3. Семантика через Wordstat

API: Yandex Cloud Search API, `POST https://searchapi.api.cloud.yandex.net/v2/wordstat/topRequests`, заголовок `Authorization: Api-Key <ключ>`. Старый `api.wordstat.yandex.net` в облачной среде отдаёт чужой сертификат — не используй.

Если ключа нет — проведи пользователя по шагам из `references/wordstat-setup.md` (создать API-ключ в AI Studio, добавить «Сетевой секрет» в среду Claude). Ключ никогда не проси прислать в чат. Проверка доступа: запрос без своего ключа должен вернуть данные, а не `Unknown api key` / `IAM token or API key has to be passed`.

Сбор: составь файл масок (по 10–20 на страницу: услуга + «под ключ», «заказать», «цена», «разработка», «создание», ниша + «для застройщика/риелтора/агентства»), затем

```
python3 scripts/wordstat.py masks.txt out.csv --region 225 --top 300
```

Регион по умолчанию — Россия (225); если клиент работает в одном городе, спроси и подставь его ID.

**Чистка интента** — самое важное. Выкинь и покажи пользователю отдельно:
- омонимы и города (`недвижимость лида` — город Лида; `квиз плиз`, `названия для квиза` — игры);
- «сам сделаю»: бесплатно, тильда, конструктор, ИИ/нейросеть, промт, курс, как сделать, примеры;
- другую услугу: `реклама в новостройках` (лифты и подъезды), `моя реклама` (доска объявлений), песни и ролики из рекламы, `сайт жк` (ищут конкретный ЖК);
- кредиты, аренду и прочее с общими словами.

Для B2B-ниш спрос маленький (десятки-сотни показов) — это нормально, говори об этом прямо.

## 4. Внедрение ключей

Сначала покажи таблицу «где → сейчас → предлагаю» и дождись согласия. Цены, сроки и факты бери только со страницы или от владельца, не выдумывай.

Куда класть, по убыванию веса:
1. **title** — главный коммерческий запрос + 1–2 уточнения.
2. **H1** — если он уже точно совпадает с главным запросом (например «Лендинг под ключ»), не трогай. Длинный H1 с перечислением ключей хуже и для людей, и для поиска.
3. **Подзаголовок/лид первого экрана** — «разработка», «создание», «продающий», ниша.
4. **H2 разделов** — «Что делаем» → «Создание лендингов, сайтов и квизов», «Тарифы» → «Цены на лендинг под ключ», калькулятор → «Сколько стоит лендинг под ключ».
5. **FAQ** — добавь вопросы, которые совпадают с запросами («Сколько стоит лендинг под ключ?», «Продвигаете ЖК под ключ?»), не дублируя существующие. Потом `faq_jsonld.py`.
6. Текст блоков — 1 вхождение на абзац, без переспама.

Огромные общие запросы («сайт под ключ», 6000+) одностраничнику не взять — не перекраивай под них оффер.

После правок сделай скриншоты Playwright на 1440 и 390: новый заголовок не должен разрастаться на 3 строки, плашки — переноситься, не должно быть горизонтальной прокрутки и ошибок в консоли. Если разросся — сократи формулировку, сохранив ключ.

## 5. Яндекс Вебмастер и Метрика

1. Пользователь добавляет сайт и присылает мета-тег `yandex-verification` → вставь в `<head>` главной сразу после viewport, опубликуй, проверь на живом сайте.
2. «Индексирование» → «Файлы Sitemap» → `https://домен/sitemap.xml` (если инструмент временно в режиме чтения — не страшно, Яндекс найдёт карту через robots.txt).
3. «Переобход страниц» → все продающие URL.
4. «Региональность» → Россия или город.
5. Через 3–5 дней — «Страницы в поиске». Новые тексты в выдаче через 3–14 дней.
6. Предложи Метрику: номер счётчика → код в `<head>`, цель `lead` на отправку формы.

## Отчёт пользователю

Коротко, по-русски, без жаргона: что поменял на каждой странице (было → стало), как выглядит на компьютере и телефоне, ссылка на сайт, напоминание про Ctrl+F5 и что сделать в Вебмастере. Выгрузку Wordstat отдавай файлом CSV.
