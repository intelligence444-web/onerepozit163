# Запуск лендинга: наш процесс

Как мы сделали ad-engine.ru (реклама для недвижимости) и ad-engine.ru/landengine/ (лендинги). Смысловую часть (аудитория, оффер, прототип) ведём по методике `metodika-lending` (этапы 0–2), техническую — по этому файлу. Если стек в методике отличается (Beget, Telegram), берём наш: GitHub Pages + Yandex Cloud + почта + MAX.

## 1. Бриф и смысл

1. Собрать у клиента: ниша, город, чек, кто клиент (застройщик, агентство, риелтор), площадки рекламы, что уже есть (сайт, CRM, кейсы, отзывы).
2. Аудитория и оффер, затем текстовый прототип по блокам — по `metodika-lending`. Утвердить прототип до вёрстки.
3. Факты только подтверждённые. Нет цифр, кейсов, отзывов — пишем пометку «пример» и просим реальные. Цены и сроки сверяем с Александром.
4. Перед добавлением блока проверить, нет ли его аналога ниже (не дублировать этапы, FAQ, тарифы).

## 2. Вёрстка

- Чистый HTML/CSS/JS без сборки. Шрифт Onest, токены цветов и радиусов в начале CSS (см. CLAUDE.md, «Дизайн-система»).
- Никаких `ad` в именах файлов, папок и классов (`ad.css`, `ad-title`, `banner`): AdBlock режет стили. У нас `main.css`, `main.js`, `serp-*`.
- Первый экран: оффер, главная кнопка (с бликом `.btn-shine`) и рядом кнопки «Telegram» и «MAX» (`.msg-btns`, `.btn-tg`, `.btn-max-chat`). На телефоне — нижняя панель с телефоном и значками мессенджеров.
- Иллюстрации — HTML/CSS-макеты с настоящим текстом и 3D-предметы (раздел 3), а не серые заглушки.
- Анимации уважают `prefers-reduced-motion`.
- Подвал общий: `partials/footer.html` + `assets/footer.css`, затем `python3 tools/sync_footer.py`. В подвале реквизиты ИП, ссылки на политику и согласие.
- После правки CSS/JS поднимать `?v=` во всех страницах, которые их подключают.

## 3. 3D-графика

1. Сгенерировать предмет в Kie (`mcp__Kie__kie_generate_image`): один предмет, мягкий 3D-стиль, сине-фиолетовые акценты под `--accent`, однотонный белый фон (для тёмных блоков — тёмный), без текста. Проверить баланс кредитов перед серией.
2. Вырезать фон: `python3 tools/cut_3d.py исходник.png assets/3d/имя.webp` (светлый фон, цвет фона берётся с краёв) или `tools/cut_3d_dark.py` (тёмный). На выходе webp до 240 px, 10–20 КБ.
3. Ставить через `<img loading="lazy" alt="">` рядом с заголовком блока, на телефоне уменьшать.

## 4. Формы и заявки

- Маска телефона, обязательная галочка согласия со ссылкой на `consent.html`, скрытое поле-ловушка `website` от ботов.
- Квиз: шаги с прогрессом, ответ с одним вариантом сразу ведёт дальше. Ответы склеиваются в поле `project` как `ключ: значение; ключ: значение` — функция раскладывает их по строкам в MAX.
- Попап с режимами (`calc`, `audit`): один попап, разные заголовки и поля.
- Сайт передаёт с заявкой `page`, `utm` (метки первого перехода, хранятся в `sessionStorage`), `ym_uid` (cookie Метрики), `referrer` — функция `visitSource()`.
- Отправка: POST JSON в Yandex Cloud Function → письмо на Яндекс Почту + сообщение в группу MAX. Подробно, с настройкой и проверкой: `references/leads-max.md`.
- После отправки — своя страница «Спасибо» у каждого сайта (вкладка открывается сразу при клике, иначе браузер блокирует).

## 5. Аналитика

- Счётчик Яндекс Метрики в `<head>` всех страниц, кроме концептов. `CONFIG.metrikaId` в скрипте.
- Цели: JS-цель на отправку формы (`lead_estate`, `lead_lend` — у каждого сайта своя) и «Посещение страницы» на свою страницу «Спасибо». Адреса «Спасибо» не переименовывать.
- Проверить, что все цели засчитываются (тестовая заявка + отчёт «Конверсии»).

## 6. Закон (152-ФЗ)

- `privacy.html` (политика) и `consent.html` (отдельное согласие), реквизиты ИП.
- Данные только в России: Yandex Cloud, Яндекс Почта, MAX. Зарубежные сервисы (Telegram-боты, Gmail, FormSubmit) — только с правкой п. 6.3 политики и уведомлением РКН.
- Новый получатель данных (например, мессенджер) — дописать в раздел «Передача третьим лицам».
- Пароли и токены только в переменных функции, никогда в репозитории и не в чате.

## 7. SEO

Скилл `seo-landing`: title, description, canonical, Open Graph, JSON-LD (`ProfessionalService` + `FAQPage`), `sitemap.xml`, `robots.txt`, `404.html`, Вебмастер. Служебные страницы — `noindex`.

## 8. Проверка и публикация

1. Playwright: 1440 и 390 (по возможности 1366 и 360) — ничего не обрезано, нет горизонтальной прокрутки, нет ошибок в консоли. Скриншоты только в `/tmp/claude-0/shots`, не в репозиторий. Локальный сервер: `python3 -m http.server 8765` из корня.
2. Тесты функции: `cd server/lead-mail && npm test`.
3. Перед пушем `git fetch origin main` и merge: в `main` может писать другая сессия. Публикация — пуш в рабочую ветку и `git push origin HEAD:main` (GitHub Pages, домен в `CNAME`). «Не публикуй» — только рабочая ветка.
4. Тестовая заявка с живого домена со ссылкой `?utm_source=test&utm_campaign=check`: пришло письмо, пришло сообщение в MAX с метками, засчитались цели.
5. Отчёт Александру: что сделано, как на компьютере и телефоне, ссылка, «нажмите Ctrl+F5».
