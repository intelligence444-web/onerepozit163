# Приём заявок: Yandex Cloud Functions → Яндекс Почта и группа MAX

Функция принимает заявку с сайта и отправляет письмо на ящик Яндекса. Данные остаются в России: функция работает в Yandex Cloud, письмо хранится в Яндекс Почте. Пароль от почты лежит в настройках функции, на сайте его не видно.

Проверка без отправки писем: `npm install && npm test`.

## 1. Пароль приложения для почты

1. Откройте [mail.yandex.ru](https://mail.yandex.ru) → ⚙ → **Все настройки** → **Почтовые программы**. Включите **«С сервера imap.yandex.ru по протоколу IMAP»** и **«Пароли приложений и OAuth-токены»**. Сохраните.
2. Откройте [id.yandex.ru/security/app-passwords](https://id.yandex.ru/security/app-passwords) → **Создать пароль приложения** → тип **Почта** → название, например «Сайт заявки».
3. Скопируйте пароль: он показывается один раз. Это `SMTP_PASS`.

## 2. Функция в Yandex Cloud

1. Зайдите в [console.yandex.cloud](https://console.yandex.cloud). Если нужно, создайте платёжный аккаунт: бесплатного лимита (1 млн вызовов в месяц) хватит, деньги не спишутся.
2. **Cloud Functions** → **Создать функцию** → имя `lead-mail` → **Создать**.
3. Среда выполнения: **Node.js 22**. Способ: **Редактор кода**.
4. В редакторе создайте два файла и вставьте в них содержимое `index.js` и `package.json` из этой папки. Зависимости установятся сами.
5. Точка входа: `index.handler`. Таймаут: `10` секунд. Память: `128 МБ`.
6. Переменные окружения:

   | Ключ | Значение |
   |---|---|
   | `SMTP_USER` | `mr.iducczeli@yandex.ru` |
   | `SMTP_PASS` | пароль приложения из шага 1 |
   | `MAIL_TO` | `mr.iducczeli@yandex.ru` |
   | `ALLOWED_ORIGINS` | `https://ad-engine.ru,https://www.ad-engine.ru,https://intelligence444-web.github.io` |

   Пароль надёжнее хранить в **Lockbox**: создайте секрет и подключите его к функции как переменную `SMTP_PASS`.
7. **Сохранить изменения**.
8. На вкладке **Обзор** включите **Публичная функция** и скопируйте **Ссылку для вызова** вида `https://functions.yandexcloud.net/d4e...`.

## 3. Подключение к сайту

Ссылку из шага 2.8 впишите в `formEndpoint` в начале `landengine/script.js`. Отправьте тестовую заявку с сайта: письмо придёт на почту за несколько секунд.

Если письма нет: **Cloud Functions** → `lead-mail` → **Логи**. Строка `smtp ...` означает, что почта не приняла пароль (проверьте шаг 1), ответ `403` — что адреса сайта нет в `ALLOWED_ORIGINS`.

## 4. Заявки в группу MAX

Функция дублирует заявку в рабочую группу MAX: имя, телефон, ответы квиза, IP, UTM-метки (по порядку `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, потом остальные параметры, например `yclid`), `_ym_uid`, откуда пришёл посетитель и страница. Метки берутся с первого рекламного перехода и сохраняются, пока открыта вкладка. Если один канал не сработал (почта или MAX), заявка всё равно принимается, ошибка видна в логах функции.

1. Бот. Создайте бота на [business.max.ru](https://business.max.ru) → **Чат-боты** → **Создать**. В настройках бота откройте **Интеграция** → **Получить токен**. Это `MAX_TOKEN`. Токен никому не пересылайте и не храните в репозитории.
2. Группа. Создайте группу в MAX, например «Заявки с сайта», добавьте в неё бота и сделайте его администратором.
3. Номер группы. Напишите в группу любое сообщение и выполните в терминале (вместо `ТОКЕН` вставьте токен):

   ```bash
   curl -s -H "Authorization: ТОКЕН" https://platform-api.max.ru/chats
   ```

   В ответе найдите свою группу по `title` и скопируйте её `chat_id` (отрицательное число). Это `MAX_CHAT_ID`.
4. В функции `lead-mail` замените код `index.js` на новый из этой папки и добавьте переменные окружения `MAX_TOKEN` и `MAX_CHAT_ID`. Токен надёжнее хранить в Lockbox, как `SMTP_PASS`. **Сохранить изменения**.
5. Отправьте тестовую заявку с сайта со ссылкой вида `https://ad-engine.ru/?utm_source=test&utm_campaign=check`. Сообщение придёт в группу за пару секунд.

Если сообщения нет: в логах функции строка `max 401` означает неверный токен, `max 403` или `404` означает, что бот не добавлен в группу или неверный `MAX_CHAT_ID`.
